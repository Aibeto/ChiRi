## 二轮：平均值改表格布局（用户反馈宽屏下左右拉开没法看）

## 六轮：断裂轴不生效 → 跨天时间回绕（真根因）

**用户**：断裂轴不生效。静态复核（computeGaps/xDisp/unX/sx 包装/命中/刻度/绘制链路）全部正确，映射函数单测也过——问题在数据侧：**`toSeconds` 返回当天秒数，跨天日志（过 00:00）`xs` 回绕非单调**，回绕处的巨大空档 diff 是负数，`computeGaps`（只认正 diff > 60s）永远检测不到——过夜日志的长时间息屏空档恰好跨午夜，断裂轴必然「不生效」。

**修法**：`parseCsv` 时间分支加回绕展开——比上一样本小半天以上（`v + off < last - 43200`）时整体 +86400（可跨多天），保持单调；null 值顺延上一个有效值。副作用修正：rebuild 顶部时间范围 `fmtClock(unX(domain.x0/x1))`（域是显示空间，直接 fmtClock 会偏）。

**验证**：jsdom 端到端集成测试（临时目录装 jsdom + stub fetch 喂合成跨天 CSV）——6 项断言全过：载入/时间模式/检测到 2 个断裂段（跨午夜 610s + 天内 250s）/回绕单调/域已压缩（1800s→966s）/无脚本错误。教训：**「秒数 % 86400」类时间解析在跨天数据上必然回绕，任何要求单调 x 的算法（断裂轴、增量 diff、域计算）都得先展开**；映射引擎没问题时要怀疑数据不变量。

## 七轮：断裂轴仍不生效 → 第二根因：文件间空洞

**用户截图**：轴上左段数据 + 中间长空洞 + 右段密集数据 → 数据是**多个会话文件**（日志归档按时段切开）。`computeGaps` 只查**文件内部**相邻行 diff，**文件与文件之间的空洞**不在任何相邻行对里——永远检测不到。

**顺带修第一版回绕规则的漏判**：`v + off < last - 43200` 半天阈值在「暂停 >12h 且恢复时钟落后不足半天」时漏判（如 22:02 息屏→次日 10:35 恢复：38100 > 阈值 36120）→ 改严格规则 `while (v + off < last) off += 86400`（时间倒退即回绕，可跨多天）。

**修法**：computeGaps 重写——① 文件内部空档（原有）；② **文件间空档**：各文件时段 [首,尾] 按 start 排序，用 running maxEnd 找相邻时段间隙（重叠/嵌套时段自然合并，不产生假空档；时间模式按文件过滤，不再因一个 index 文件整体放弃）。

**验证**：run3（双文件，文件间 12min 空洞 + 文件内 301s 空档）5 项全过；run2（跨天回绕）回归 6 项全过。测试脚本报过一次假 FAIL——是测试断言自己的分钟换算错了（21:07:44=1267.7min 不是 764），代码是对的。**遗留**：跨天且时钟重叠的多文件无法从时钟判日序，不自动对齐（会破坏同日叠图对比）；如需要得靠文件名内嵌日期。

## 八轮：短暂断裂用虚线连接

**用户**：当出现短暂断裂（< 60s 压缩阈值）时用虚线表示。实现：draw() 曲线循环里，相邻采样点时间差超过 `gapThresh = max(采样间隔中位数×4, 10s)` 时，实线在此断开（open=false），两侧点连成一条虚线段（`app__dashseg`，同色 3 4 dasharray、0.75 透明度），与主实线路径并存。

**两个教训（调试中抓到）**：① **断裂判据不能用行距**——空档的行根本不在 CSV 里，剩余行索引连续（maxRowDiff=1），断裂只体现在时间差；② **`prev` 存了 `px/py` 却读 `prev.x`** → `NaN > gapThresh` 恒 false，功能静默失效——测试断言（dashsegs≥1）直接抓住。中位间隔基准防抽稀误判：密集区抽稀步长 step 会把相邻采样点时间差放大到 step 秒，`med*4` 与 10s 下限兜底，缺测多到污染中位数时退回固定阈值。

**验证**：run4（30s 空档→不压缩、虚线段出现、双路径共存）4 项全过；run3/run2 回归全过。

**实现**：`buildSeriesPath` 增加 `dm`（半透明段）输出——筛选生效（`isFiltering()`）时逐采样点判定 `rowVisible(file, p.row, p.raw)`（点自带 raw 行数组，无需回查），**段两端任一端被筛掉即整段降透明**；实线在降透明区间两侧断开重连（与虚线断裂同模式），三条路径并存：`d` 实线 / `dd` 断裂虚线 / `dm` 半透明（`.app__dimseg` opacity .5，同色）。规则优先级：时间gap虚线连接 > 降透明（「无数据」语义更硬）。缓存键 `pk` 纳入**筛选签名**（五项筛选值拼接；未筛选时 fk='' 共享缓存）；**筛选提交必须 draw()**——renderTable 不重画图表，漏掉会导致图不反映筛选（run10 首跑抓到），监听器统一走 `commitFilter() = renderTable(true) + draw()`。

**测试踩坑**：隔行交替数据下每段都含被筛行 → 整条都该降透明（M=1 是对的）；要验证「断开重连」得用块状数据（0-39 a / 40-69 b / 70-99 a）。run10 五项全过；run8（10 万行）回归 8 项全过（深跳转 181ms）。

## 十五轮：筛选空前缀兜底（表格空转修复）

**用户**：筛息屏后表格不显示任何条目，点一下图表（触发高亮/ensureRendered）才出现——要求以此类推排查同类问题。

**根因**：前缀分块渲染 + 筛选的组合——匹配行全在文件后部时（日志开头全是亮屏、筛息屏），首块 800 行扫不出匹配 → 表格空转；「继续载入」按钮是隐藏的，用户没有前进手段；点击图表才触发 ensureRendered/窗口切换。**三级搜索、电源筛选同病**。

**修法**：`extendScanForMatches(cols, minShown=ROW_CHUNK)`——筛选生效且已渲染不足 minShown 时继续向后扫块（renderRows 只物化匹配行，DOM 随匹配数而非扫描量增长；guard 400 块上限）。挂三个点：renderTable（reset/append 后）、repaintTable（**顺带修正其越窗重渲**：改 `renderRows(renderFrom, rowsShown)` 遵循窗口语义，否则切窗后 toggle 表头会把全量前缀重新物化回去）、renderWindowAround（点击被筛掉的点时窗口内 0 匹配的兜底）。未筛选时不动作，顺序分块语义不变。

**验证**：run11——匹配行全在 900-1000 的 1000 行文件筛息屏：不点图表直接显示 100 行、rowsShown 推进到文件尾、统计「100/100 · 筛选中」；点被筛掉的行不破坏表格；三级搜索同类场景同修。run7/run9/run8 回归全过（深跳转 317ms）。

## 三轮：高亮行图表虚线 + 原始数据搜索/筛选

**用户**：① 高亮选中原始数据行时图表对应位置也要虚线标识；② 原始数据加搜索和筛选。

**实现**：① `draw()` 悬停准星块后加高亮标识——`state.highlight` → 找该文件可见 series → `points.find(q => q.row === hl.row)`（**series 点自带 row 索引**，这是联动定位的现成通道）→ `app__markline`（信息色长虚线 6 3，与准星 action 色密虚线 3 3 区分），出视图范围（`hx < M.l || hx > w-M.r`）不画；`setHighlight`/`toggleHighlight` 都补 `draw()`（原来只 paintHighlight 表格侧）。② 工具栏加 `tableSearch`（type=search，150ms 防抖，任意列原文子串、不分大小写）+ `chgFilter`（charge 原文四态）；`rowVisible()`（`f.headers.indexOf('charge')` 每行调用略费但可接受）+ `countMatches()`（筛选生效才全量扫）；renderRows 跳过不可见行；tableStat 改 `已显示 {tbody.children.length} / {matched} 行 · N 列 · 筛选中`；搜索/筛选都走 `renderTable(true)` 重扫。注意点：筛选时 `rowsShown` 语义变成「已扫描行数」，显示行数用 tbody 实子节点数，两者别混。
