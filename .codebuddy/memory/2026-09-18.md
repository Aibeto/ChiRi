## 三十六轮：倍率全链路审计 + PowerAVG 为空的诊断

**① 倍率审计（结论：没有隐藏倍率）**：`节点 → 报告功率` 上的全部因子＝① 私有节点存储 ×1000（mV/mA → µV/µA，只为与标准节点同口径；随后被电压的 `/1000` 与电流的 `/D_c` 精确抵消，D=1000 时净效果为 1）；② 标准节点固定 `/1000`（µV→mV，ABI）；③ `voltage_divisor` / `current_divisor`；④ `voltage_double` / `current_double` 的 ×2（仅 `!oplus_chg`，默认关）；⑤ `W = |mA| × V`（`batt_power_w`）。`logger::power_avg_update` 内部只有加权递推（`(旧×10+新)/11`、`(旧×n+新)/(n+1)`），无任何缩放。默认配置下与改动前逐位一致。

## 四十三轮：双电芯求和 → 两节平均（用户质疑，成立）

**用户质疑**：电池通常 ~4V，两节求和成 8V 不合理，是否该取两节平均再乘电流？→ 成立。

**证据**：样本 `3841 / 电流 258 / 3835`（下标 6/8/11）——求和 = 7.676V × 0.258A = **1.98W**；平均 = 3.838V × 0.258A = **0.99W**。两节仅差 6mV（0.16%），且用户标准节点在 ~4V 域 → 求和属「整包串压」口径，与系统认的单节域不同量级，功率翻倍。

**物理**：下标 6/11 = 两节各自端压（都在 4V 域），下标 8 的电流是**整包/单节同一口径**的电流 → `V × I` 要用单节域电压。取和等价于「电流是整包电流而电压用串压」，只在标准节点也报 ~8V 的 2S 直串机型上成立。

**改法**：`read_oplus_bcc` 双电芯分支 `(v0 + v1) / 2`（`v1 > 0` 才参与，非正则只用 v0）+ 注释写明判据；同步 `[options]` 文档、`common.rs` / `chiri/config.rs` 字段注释、四份 meta 模板、AGENTS、MEMORY（顺带清掉 MEMORY 同段里过期的「×1000 归一」描述——与后文「已删除归一」自相矛盾）。WebUI 两条 hint 已是中性措辞（不含求和/平均），未动；顺手去掉 zh `battery.oplusDualCell.hint` 的首空格。

**上机自检**：`adb shell dumpsys battery | grep -i voltage` → 3841mV 级 = 单节域（平均对）；7680mV 级 = 2S 直串（改回求和）；或比私有节点 P 与「标准节点 V × I」（±20%）。验证：cargo check ✓。
