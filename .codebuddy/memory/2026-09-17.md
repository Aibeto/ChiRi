## 分析：与 system_server / ThermalManagerService 的关联与死锁可能性

结论：**无关联、无死锁可能**。证据：① 全仓库无 binder/dumpsys/service call；`system_server` 只出现在 affinity 黑名单与 app_detect 过滤（主动规避，注释明说线程迁移系统进程会卡死）；② thermal 只读 `thermal_zone*/temp` 与 `battery/temp`，不写 cooling_device/cur_state → 不与 ThermalManagerService 抢 cooling；③ uprobe 用 `UProbeScope::OneProcess` 只挂前台 app 的 `Surface::queueBuffer`（fps_monitor.rs:159）；④ 无循环等待路径：`shared_config` 读锁内的 sysfs IO 无重入锁，governor 单线程独占，`down::is_down()` 原子量。

真正的风险是**竞争**非死锁：`write_cpuset_cpus`（触发内核 rebuild_sched_domains + 2s 保留核纠偏）与 system_server 的 cgroup 操作并发 → 偶发短卡顿；`shared_config.read()` 持锁内大量 sysfs IO → 内核侧慢时热重载延迟。

## 生产就绪审查（子代理终审 + 修复）

自查先发现一个关键顺序 bug：**ModeChange 的 sync（governor→performance）放在 CLG release 之前**——CLG release 会恢复它 init 时快照的 schedutil，把 performance 覆盖掉。已修：sync 拆两半——「离开 lab 的 release」放接管逻辑前（后续 CLG init 才能快照到 schedutil）、「进入 lab 的 activate」放接管逻辑后；息屏同样生效（接管逻辑跳过但调速器切换不受屏幕状态影响）。

子代理终审（生产视角：崩溃/状态机闭环/sysfs 边界/退化场景/一致性/脚本）确认崩溃风险面干净（无 unwrap/索引/溢出热点；panic 有 catch_unwind+退避+收尾；sysfs 写失败全降级；非 ChiRi 走 Yumi 不进新代码；8998 prime 空区间有守卫），但揪出 1 P0 + 3 P1，已全部修复：

1. **P0 lab 分组退出后 affinity 快照污染**：ModeChange 离开 lab 只 release governor/GPU，没调 `lab_static_deactivate` → lab 分组值留在各组，后续 boost/fas 的 ensure_snapshot 把 lab 值当「系统原值」记录 → top-app 永久停留大核、重启前无自愈。修：离开分支加 `lab_static_deactivate()`（在 governor/GPU release 前，顺序：先恢复组 cpus）。
2. **P1 FAS 延迟期同包返回不续期**：同包回前台走 PackageSwitch 同包去重/1s 巡检同包 no-op，exit_deadline 不清 → 到期把正在前台的游戏拆掉重建。修：`renew_if_same_pkg()`（fas_manager）+ 1s 巡检同包续期 + PackageSwitch 同包即时续期（借用问题先 clone active_pkg）。
3. **P1 FAS 延迟期息屏到期零接管**：tick 消费在息屏时跳过接管且 doze 未初始化 → 整夜零调度。修：tick 超时分支三分（lab 不门控亮屏 / 亮屏 apply_mode_takeover / 息屏 CLG doze 低功耗配置，与 fas_enabled=false 息屏分支同款）。

## 补充：调速器变更的「由 -> 到」info 日志

应要求把 GovernorGuard 的聚合计数打点（governor-activated/released）改为**逐 policy 的由 -> 到**：activate 时 `governor-switched = [Governor] P{ $pid } 调速器 { $from } -> performance`、release 时 `governor-restored = [Governor] P{ $pid } 调速器 performance -> { $to }`（zh/en 同步，原两 key 删除）。残留清理（performance -> schedutil）保持 warn 级（异常语义）。FastLock/CLG 的 governor 写入（schedutil）未加同款日志——它们有各自快照恢复，需要时再扩展。
