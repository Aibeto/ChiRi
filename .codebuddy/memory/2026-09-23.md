## 二：解决 4 处历史既有问题（用户「解决」）

1. **comm 切片污染（affinity.rs `sample_one_tid`）**：`text[1..close]` → 首 '(' 与末 ')' 定界取 `text[open+1..close]`。旧行为把「tid 尾部+` (`」混进 comm（tid 12345 → `"2345 (RenderThread"`），连锁 `is_key_thread`（KEY_THREAD_COMMS 全等）与 `is_affinity_blacklisted`（精确条目）恒不命中、@A/@S 帧 comm 失真。**行为影响（预期内）**：关键线程白名单（RenderThread/GLThread/GameThread/UnityMain/UnityGfxDeviceW）与黑名单精确条目从「形同虚设」恢复生效；正则黑名单本就 substring 匹配，行为不变。连带删掉 mod.rs 的 `clean_comm` 防御层（根因修复后它会误伤含 `(` 的合法 comm）。
2. **pending 补偿多算（cpu_monitor.rs `compute_tgid_util`）**：旧「raw 差分 + 当前 pending」恒多算 pending(t0)（上轮已计过），改 adj = raw + pending 差分（基线存 adj，与降级路径 `compute_thread_level_util` 同口径）；变量更名 `last_tgid_run` → `last_tgid_adj`。**行为影响**：前台 util 系统性高估消失，FAS 输入更准（util 略降属修正而非回归）。
3. **pin_self_dedicated/unpin_self 分叉（core_ctl.rs）**：新增 `self_pinned_tids` 成功清单（只记成功、每次重建），unpin_self 按清单逐个恢复、非 ESRCH 失败留清单重试；不再以 `self_pinned` 总开关短路——部分钉定失败时已钉线程永久滞留单核掩码的通路关闭。
4. **unpin_core/cleanup_thread/demote 写失败清状态（affinity.rs）**：非 ESRCH 失败保留状态（home/钉核计数/moved_group/条目）待 departed/gone/stale 路径重试，成功或 ESRCH（线程消亡）才清；内核掩码与状态表不再永久分叉。demote 的 `moved_group` 同族问题一并修（原无条件清除）。

4. 触摸升频地板 = `perf_init + tiers × 0.05`（`compute_touch_boost_floor` 用 perf_init 做基线），
   且被 perf_ceil 钳制——所以「稳态压低 + 触摸拉满」的上限就是 ceil。

**已实施（8550 default 档 + playback 特调）**：

| 项 | 旧 → 新 |
|---|---|
| default `perf_ceil` | 0.80 → **0.60** |
| default `per_cluster.little / big / prime` | 0.70 / 继承0.80 / 0.65 → **0.50 / 0.60 / 0.45** |
| default `headroom_factor` | 1.05 → **1.00** |
| default `perf_init` | 0.25 → **0.35**（喂触摸地板） |
