## WebUI 重构计划评审

对照 daemon 源码逐条核对契约基准的结论：

- 写错的：status.csv 实际 21 列（`src/logger.rs` STATUS_HEADER：timestamp..freq_trans），计划写的是 22 列。
- 漏掉的，这条影响较大：status.csv 与 devimp 都是 Chiri 专属产物（status_log_snapshot 唯一的调用点在 `src/chiri/mod.rs`，devimp 的写入点也全在 chiri），Yumi 设备上不存在。
- 漏掉的：status.csv 的列语义（首行表头、type 恒为 snap、本地时间 HH:MM:SS.mmm、缺测为 `-`、screen_on/clg_active 取 0/1、package 可为空）。
- 漏掉的：daemon.log 行格式 `[YYYY-MM-DD HH:MM:SS] [LEVEL] [module] msg`（本地时间），50MB×4 轮转；special_tuned.yaml 行格式 `包名:模式:回退`、fas_whitelist.yaml `包名:配置名`、devimp 文件名 `devimp_<pkg>_<MMDD-HHmmss>.log`。
- 写得含混的：current_mode.chr 的两个写入方其实是两套调度器（chiri/scheduler）各一处写入逻辑。
- 已核对无误：daemon.lock flock 存活判据、active_config.chr 启动写一次无换行、rules.yaml 只读、meta 7 字段严格校验+非法整体覆盖、inotify 监听 CLOSE_WRITE|MOVED_TO、watchdog.pid 先杀看门狗再 killall yumi、action.sh 恢复入口、日志归档与量级、特调/FAS 可用性对 UI 不可见。
- 实现级风险：① flock 探测必须"带命令、结束即释放"（`flock -n FILE true`）；Android 依赖 busybox flock，需探测可用性；② 写 meta.yaml 建议 tmp+mv 原子替换、多字段一次读改写+前端串行化。
- 建议：四步之前先做 Svelte 5 + Vite + ak-ui 最小冒烟；确认 svelte-i18n 对 Svelte 5 runes 的支持（后改为自实现 runes i18n）。

## WebUI 重构实施（Svelte 5 + ak-ui，已完成）

按计划四步实施：骨架 → 契约层 → 数据层 → 界面 → 走查。

- 骨架：`webui/` 原地重写（保留目录名与 dist 输出路径），依赖 svelte 5.57 / vite 8.3 / ak-ui **1.0.0（锁定，未用 @next，因为 next 只是 rc）**/ vitest 5 / svelte-check；旧 Vue 源码、`components.d.ts`、`tsconfig.app|node.json` 全部删除。
- 契约层：`kernel/shell.ts`（可注入 `ShellRunner`）+ `contract/{paths,errors,read,meta,daemon,sources}.ts`。读取三分类 Ok/Absent/Failed；meta 写入 = 顶层行替换 + `tmp→rename`（临时文件后缀 `.webui.tmp`，避开 daemon 自身的 `<name>.tmp`）；存活探测用 `flock -n FILE true`，缺 flock 时报「无法判定」而不退回 pidof。
- 数据层：status.csv 21 列解析、daemon.log 行解析与级别过滤、模式派生（clg/fas/special/unknown）、两个白名单解析、rules/module.prop 解析、应用标签合成；均为纯函数以便单测。
- 界面：四屏 + hash 路由 + runes i18n（界面语言与 `meta.language` 解耦）；复用 ak-ui 的 `.ak-card/.ak-status/.ak-tag/.ak-notice/.ak-choice--switch`，按钮与深色适配在 `[data-ak-ui]` 作用域内把硬编码色映射回 `--ak-*`；日志页局部 `data-ak-ui="terminal"`。
- 验证：`npm test` 38 项断言通过、`svelte-check` 0 错 0 警、`vite build` 通过（CSS gzip 18KB / JS gzip 54KB）；用 agent-browser（本机只有 Edge，通过 `--executable-path` 指定）走查四屏 + 5 种场景（chiri / yumi / empty / error / daemon-stopped）+ 级别过滤。

遇到的问题与决策：

1. **js-yaml 5.x 无 default 导出**（只有命名导出 `load`）→ 全部改成 `import { load as loadYaml }`，并卸载与之冲突的 `@types/js-yaml`（v4 用 `export =`，会掩盖 default 导入的类型错误）。
2. **ak-ui 表单控件是硬编码浅色、按钮固定 150×50 + 重阴影** → 在 `[data-ak-ui]` 作用域内把颜色映射回 `--ak-*`；按钮用 `.btn` 覆盖尺寸/阴影/配色并保留 `.ak-button` 的交互语义。
3. **`wait --load networkidle` 永不完成**（Vite HMR 长连接）→ 走查改为固定等待 + `eval` 读 DOM/统计节点。
4. **界面把「无记录」与「模式名未知」混为一谈；读取失败却显示「通用机型」** → 改为设备形态三态（chiri/yumi/unknown）+ 区分文案，走查已复验。
5. **删除旧文件的命令与写新文件并发执行，导致刚写的 `env.d.ts` 被删** → 已重建；后续避免对同一路径「删除 + 写入」并行。
6. ak-ui 的 `.ak-tag` 默认 `uppercase` 会把模式名/配置名改大小写 → 覆盖为 `text-transform: none`（标识符保真优先于样式特征）。
7. 未引入 `kernelsu` npm 包，改用仓库内原有的本地桥（TS 重写为 `src/kernel/ksu.ts`）。
8. 移动端（375 视口）底部导航横向溢出到 604px。根因是 ak-ui 的 `.ak-button` 固定 `width: 150px`，导航用了 `.ak-button` 却没加项目类；加 `width:100%` 后 0 溢出。日志终端与快照表在窄屏也改为重排（隐藏模块列/负载列）而非横向滚动。
9. 写入后"是否被守护进程重置"的判据原本比对整文件 JSON，会把正常改动误报成"已恢复默认" → 改为按字段比对「写入前值 + 草稿」的期望值。

最终验证：42 项断言（含新增 i18n 完整性 4 项）全过、`svelte-check` 0 错 0 警、`vite build` 通过（CSS gzip 18.3KB / JS gzip 54.3KB）。
遗留：截图环节被中断（走查以 DOM/文本校验为主）；dev server 可能仍在 5173 运行需手动结束；agent-browser 以 `--no-save` 临时安装，未写入 package.json。
